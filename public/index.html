The problem, stated plainly

Opening a shop online still feels like opening a shop in 2009

Consider Maya. She propagates monsteras in her apartment and sells cuttings to neighbors. She knows plants; she does not know product photography, SEO descriptions, pricing psychology, checkout integration, or bookkeeping. Every existing platform hands her one of two bad deals: a "simple" storefront builder that still makes her write every listing, set every price, and answer every DM herself — or a "done for you" marketplace that takes a cut, owns the customer relationship, and buries her shop on page forty. The AI wave was supposed to fix this, but most AI commerce demos are chatbots stapled to a buy button: the AI doesn't know the inventory, the payment doesn't know the conversation, and the seller learns nothing from any of it. Meanwhile PayPal already moves money for millions of small businesses, and modern LLMs can genuinely write, recommend, and reason — but almost nobody has wired the two together so that the AI sells from the live inventory and the money lands in a ledger the seller can actually read. That gap is the whole reason ShopGenie exists.

So we built the smallest thing that closes it end to end: one sentence in, stocked shelves out; one vibe-heavy question in, a curated cart out; one capture call, and the till receipt prints itself into a ledger with AI notes on what just happened. Nothing in that loop is a mockup. The catalog persists, the agent reads it live, the order hits the PayPal API (or an identical-contract mock when no keys are present), and the dashboard counts real rows. If you remove the AI, there is no inventory and no salesperson. If you remove PayPal, no money moves and there is nothing to count. Both integrations are load-bearing, which is exactly what the hackathon asks for.

Stall 1 · Stock it

Wish a catalog

Type one line about the business — "plant store for apartments", "handmade candles", "sticker art shop", "cozy coffee corner". The generator returns six products with names, USD prices, categories, emoji marks, and sub-90-character descriptions, and replaces the live shelves instantly. With an OPENAI_API_KEY set, a real model writes the copy in strict JSON; without one, a built-in themed stub produces the same JSON contract, so the demo, the judging, and the video all work offline. Try three different ideas in a row and watch the whole store re-theme itself in seconds — that re-theming speed is the point. A seller who pivots from candles to bath soaks on a Tuesday night should not spend the weekend rewriting listings.

Stall 2 · Sell it

Let the agent sell

The counter agent reads the live catalog — not a cached copy, the actual shelves — plus whatever is already in the cart. A shopper writes the way people really write: "gift under $25 for a plant lover", "something cozy for my dad who drinks too much coffee", "cheapest way to try everything". The agent extracts the budget, matches keywords against names, descriptions, and categories, recommends one to three picks with prices and a running total, and drops its top pick directly into the cart. Then the shopper checks out: real PayPal Smart Buttons when sandbox credentials exist, or a one-click mock capture that runs the identical server path (create order → capture → ledger write) with zero keys. Either way a paper receipt renders with line items, and the signature PAID stamp slams down on it.

Stall 3 · Count it

Count the till

After close, the dashboard answers the three questions every seller asks: how much came in (revenue), how many people paid (orders), and how big the average basket was (average ticket). Below that, a sortable, filterable AG Grid ledger lists every capture with its PayPal order id, amount, currency, status, mock-or-live flag, buyer note, and timestamp. And because raw rows don't tell you what to do next, an AI closing-notes panel writes three bullets every time it loads: who your best seller is, one concrete pricing or bundling move to lift average order value, and the single next action worth taking. Run a second sale and watch every number move — the dashboard is live, not a screenshot.

Under the counter

Six things that make it real

Same-contract stub AI

Every AI endpoint — generation, chat, insights — serves the exact same JSON whether the key is present or not. That means the demo never says "configure an API key to continue", judges never get stuck, and swapping stub for model changes the words without changing a single line of frontend code. The provider badge in the header always tells you which brain is working.

Server-side PayPal truth

Orders are created and captured with the PayPal REST API using short-lived OAuth tokens, never by trusting the browser. Secrets never leave the server; only the publishable client id is exposed for Smart Buttons. Mock orders use the same ledger-writing path, so a mock sale and a sandbox sale are indistinguishable downstream.

A ledger, not a log line

Captures persist as structured transactions — order id, items with quantities, buyer notes, timestamps — in a JSON ledger the dashboard queries. Filter by status, sort by time, search notes. This is the artifact a real seller needs at tax time, and it's the artifact that proves the payment loop actually closed.

Zero-build frontend

No bundler, no framework, no build step. Three pages of vanilla HTML, one stylesheet, one script, AG Grid from CDN. A judge clones, runs npm install && npm start, and is clicking through a sale in under two minutes. Nothing to compile means nothing to break.

Static-safe offline mode

Hosted on Cloudflare Pages with no backend, the tool detects the missing API and switches to an in-browser twin: seeded catalog, localStorage ledger, mock captures, same UI, same flow. One codebase serves both the full-backend demo and the always-on static link. The docs explain exactly which mode you're in and how to tell.

Sponsor tracks, honestly earned

AG Grid powers the transaction ledger judges actually sort and filter. Render hosts the backend with a checked-in render.yaml. A Postman collection documents every endpoint. Cloudflare Pages hosts these very pages. Each integration does visible work in the demo rather than sitting in a dependency list.

Why judges should care

PayPal and AI, both load-bearing

Hackathon projects love to name-drop two platforms while only needing one. Here's the load-bearing test for ShopGenie, stated as plainly as we can. Remove the AI: there is no catalog (a seller would have to hand-write six listings), no salesperson (shoppers browse a dead grid), and no closing notes (the dashboard is arithmetic without advice). The app becomes a static product list with a PayPal button — a weekend project, not a product. Remove PayPal: the agent can recommend all day, but no order is created, no money moves, no receipt prints, and the ledger stays empty forever. The dashboard — a third of the app — has nothing to count. What remains is a chatbot with opinions and no cash register.

Against the published criteria: technological implementation shows in the Orders v2 create/capture round-trip plus three distinct LLM call sites with a graceful stub fallback; design shows in a coherent night-market identity carried across landing, tool, docs, and even the launch video; potential impact shows in the millions of solo sellers for whom "one sentence becomes a shop" removes the exact weekend of drudgery that stops them from starting; innovation shows in treating the agent as staff with register access rather than a help widget; presentation shows in a demo that completes a real sale in a minute with zero keys. That is the case, and the tool is the evidence.

Fair questions

Asked, answered

Does any real money move?

No. Everything runs against the PayPal Sandbox or the mock path — both move zero real dollars by construction. The header badge always shows whether the till is in mock or live-sandbox mode, so there is never ambiguity about what just happened.

What if I have no API keys?

Then you get the full demo anyway. The stub AI writes themed catalogs, answers with budget-aware recommendations, and computes ledger-backed insights; mock PayPal orders flow through the identical capture-and-record path. Add keys later and the same buttons do the real thing.

Why vanilla JS instead of a framework?

Judging logistics. A hackathon demo is evaluated by strangers on unknown machines in limited time. Eliminating the build step eliminates an entire class of "it worked on my laptop" failures, and the whole app remains readable in one sitting — which matters when evaluators read code.

Can this become a real business?

The honest roadmap: multi-seller accounts, PayPal Invoices for custom quotes, payouts for marketplace splits, webhook-driven fulfillment, and persistent hosted Postgres instead of the JSON ledger. The architecture already isolates those seams — src/paypal.js, src/ai.js, and src/store.js are the three files that would grow. See the docs roadmap section for the full list.

Where do I start as a judge?

The tool, Stall 1, press "Run full demo". Sixty seconds later you'll have seen every integration fire. Then read the docs for the API table and the Devpost checklist.

After the hackathon

What we'd build with another month

First, real seller identity: accounts, multiple storefronts per seller, and per-store ledgers instead of one shared till. Second, deeper PayPal surface: Invoices API for agent-negotiated custom quotes ("the agent agreed on $45 — here's your invoice"), subscriptions for the workshop seats and plant-food refills the stub catalogs keep inventing, and webhooks so completed payments trigger fulfillment emails without polling. Third, a real database and hosted search so the ledger scales past demo size and shoppers can search across thousands of products. Fourth, evaluation: side-by-side stub-versus-LLM quality checks on generated listings, so the "same contract" promise stays honest as models change. Fifth, accessibility and i18n passes — the night-market look must survive screen readers and right-to-left layouts before it touches a real seller's livelihood. None of that is needed to prove the concept; all of it is scoped, filed, and waiting.
